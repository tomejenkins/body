# MVP readiness and next roadmap

## Decision

Body's online strength-training core is substantially implemented and locally exercised. It is **not yet an MVP launch sign-off**. Required Superset Support, manual cardio, trial, subscriptions, promotional/lifetime entitlements and administrator operations are not implemented. Physical-device connectivity, production Auth/email, operational recovery and dependency review remain gates. This audit does not make those requirements optional.

The Phase 7.6F changes preserve the existing workout design and authoritative data engines. A public offline fallback is not offline workout recording. Recommend option **B**: separately controlled bounded durable drafts, after physical-device validation, rather than enabling a full offline mutation queue.

## Recommended development sequence

1. **7.7A — Connectivity hardening and release gates.** Mandatory invalid-completion checkpoint and local transport/runner hardening are implemented; physical/hosted and advisory gates remain open. See [contracts](phase-7-7a-connectivity-hardening.md). Physical iPhone Safari/PWA and Android checklist, production-region sanitized request waterfall, scoped action transport wrappers, test-runner correction and compatible tool-advisory remediation. Verify error reporting without logging credentials or training payloads. Check both uncertain commit and no-commit retries for closure, switch and retention.
2. **7.7B — Bounded durable drafts.** Explicit account/private storage contract, byte/session/TTL caps, foreground recovery, eviction/termination/logout/upgrade tests. Keep drafts unconfirmed. Do not introduce automatic replay or offline completion under the name of caching. Product can launch online-only only with an explicit tested connectivity limitation.
3. **7.7C — Superset Support MVP.** After performance/connectivity reliability and Phase 7.6F.1 logger simplification, review and implement exactly-two-movement grouping from Workout Home. Preserve independent sets, exercise IDs, PR/progression, timing and safe ungrouping; grouping is navigation/structure only. This is required before final MVP launch sign-off. No Superset implementation is included in 7.6F.1.
4. **7.7D — Manual cardio MVP.** A separate duration evidence contract and Add Cardio slot for required modes. Integrate session timing/history without fabricating strength sets, PRs or program prescribed completion; no HIIT or activity-platform sync.
5. **7.7E — Entitlement foundation and trial.** Server-authoritative entitlement decisions, exact 14-day trial policy/time source, protected grant provenance and audit receipts. Define shared denial/read-only rules and offline Auth policy before paywall UI. No editable client/admin flags.
6. **7.7F — Subscription integration.** Provider selection and scoped approval, signed webhook verification, idempotent event receipts, out-of-order/cancellation/refund/reconciliation tests, protected secrets and support recovery. Enforce the shared entitlement model server-side; a hidden client button is not access control.
7. **7.7G — Promotions, lifetime access and administrator support.** Build on the same entitlement/grant authority. Atomic redemption limits/durations, authorized administrator roles outside user metadata, administrator assignment process, private support boundaries and minimal audit data. Never expose service-role credentials in UI.
8. **7.7H — Privacy and operational launch review.** Data export/account deletion design, retention/backups policy, support/contact/recovery, auth delivery, rate limits, accessible device walkthroughs, staged migrations, monitoring/alerts, restore drill and rollback/version-update rehearsal. Re-run all suites on the release candidate and obtain a concrete go/no-go.

Dependencies: retention eligibility remains the shared evidence authority; durable drafts must reconcile retention/lifecycle revisions rather than create a second execution model. Cardio needs its own supported measurement contract before analytics consume it. Trial, subscriptions, promo and lifetime access all depend on one protected entitlement model; do not create parallel booleans. Admin UI depends on that role/grant model and authorized audit/read boundaries. A full offline replay ledger (if later justified) needs server command receipts and conflict design before any client queue is enabled.

Optional improvements after gates: measured Look Back payload trimming, safe request-local loader deduplication, physical profiling of large sessions and narrowly justified query indexes. V2: full offline mutation synchronization, native packaging, HIIT, community/Feed and advanced builders. None is smuggled into this audit.

## Confirmed Superset MVP contract — design review required

Superset Support was requested after Phase 7.6F began. It is required MVP scope, not a V2/V3 feature, and is roadmap-only in Phase 7.6F.1. This logger refinement adds no Superset schema, UI, placeholder, navigation or execution behavior. Manual cardio, 14-day trial, subscriptions, configurable promotions, lifetime-free grants, administrator support and existing security/operational launch gates remain required.

The future **Combine Movements** action originates on Workout Home and groups exactly **two movement patterns**. For example, Superset A contains A1 Flat Push / Barbell Bench Press and A2 Triceps Extension / Cable Pushdown. Preserve movement-first identity, each selected canonical exercise, independent sets/weights/reps, separate completion and unequal set counts. Efficient A1/A2 navigation must not create completed sets, merge volume/PR metrics, select exercises automatically or change session pause/timing semantics. Users must be able to separate the group without losing actual training. Favorites, History, program attribution and existing eligible performance/progression must remain compatible.

Before implementation resolve:

- Group only already selected movements, or also allow grouping before exercise selection?
- Where does Combine appear on Workout Home, and how are exactly two distinct movement identities selected/validated?
- How does the logger switch between A1 and A2 without overriding the user's actual selection or queue?
- How are unequal set counts and partial completion displayed without auto-completing or inventing sets?
- Can grouping change during active training, and what locks/revisions protect a second device's changes?
- How does History retain grouping independently from original performance evidence?
- How do reusable Favorite snapshots preserve grouping safely without copying actual performance?
- Can immutable program templates prescribe grouping, and how do ad-hoc group choices preserve original source day/slot identity?
- How does ungrouping preserve every existing recorded set, ordering and canonical exercise reference?

Dependency order: connectivity and deliberate draft recovery → simplified logger → Superset design/validation → bounded grouping/navigation implementation → Favorites/History/program compatibility → regression/device review → launch sign-off. Supersets must reuse the authoritative workout engine; grouping is not a combined performance metric or a second completion engine. Define a minimal migration only in that future phase after the model review. Circuits, giant sets and combined HIIT routines remain later scope.

## Physical-device release checklist — all unverified here

Run on iPhone Safari, installed iPhone PWA, Android Chrome and installed Android PWA. Record OS/browser/version, device, connectivity profile and actual results; never label desktop emulation physical testing.

- Install/launch online, then launch disconnected after a prior visit; first-ever offline visit and evicted storage must fail honestly.
- Open a real test workout, select an exercise, enter precise weight/reps, lose connection before/during/after save, reconnect and explicitly retry. Verify server evidence and no false Saved.
- Enter a draft, background/foreground, lock/unlock, terminate/relaunch, memory-pressure/low-storage simulation and eviction. Record exactly what survived; no durability promise beyond tested behavior.
- Test uncertain save with another device's later edit; retain both the current remote value and recoverable local input.
- Keyboard opening/closing, touch targets, scroll focus, 200% text/Dynamic Type, safe areas/landscape and fixed-footer geometry.
- Pause/resume, interrupted Finish/Abandon, Favorites, switching programs, archive/restore/delete and history/back-forward during outages. Refresh to resolve an uncertain consequential operation.
- Auth expiry/recovery, explicit logout, a different account on the same device, back/forward/reload and shared-device privacy. Inspect Cache Storage: public allowlist only.
- Deploy-version rehearsal in staging: old window remains safe, new worker waits, close old windows, activate new version, remove prior owned cache, preserve online operation with caching denied.
- VoiceOver/TalkBack labels, focus order, announcements and Escape/outside dismissal; reduced motion; high contrast and poor connection feedback.
- Verify production email, monitoring/alerts, cold/warm edge/server/Auth/DB latency and backup restoration. Do not use production customer data for probes.
